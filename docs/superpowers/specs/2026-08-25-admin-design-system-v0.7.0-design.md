# 어드민 디자인 시스템 v0.7.0 설계 — 폼 입력 가족

## 배경

지금 등록된 컴포넌트는 `Button` 하나입니다. 작업대의 목적이 "디자인 시스템이 제대로 서 있는지 눈으로 확인하는 것"인데, 부품이 하나뿐이면 확인할 것이 거의 없습니다.

이번 회차는 폼 입력 세 가지를 더합니다 — `Input`, `Select`, `Checkbox`.

세 개를 한 묶음으로 다루는 이유가 있습니다. **서로 상태와 토큰을 공유합니다.** hover·focus·disabled·오류가 세 컴포넌트에서 같은 모양이어야 하고, 그 일관성은 하나씩 만들어서는 드러나지 않습니다.

그리고 이 셋이 **아직 아무도 쓰지 않는 토큰을 처음 씁니다.** `--color-input`과 `--color-ring`은 Color Role의 `Line` 갈래에 정의되어 있고 문서에도 적혀 있지만, `Button`이 쓰지 않아 실제로 성립하는지 확인된 적이 없습니다. 이번 작업이 그 검증입니다.

## 의존성

`Select`와 `Checkbox`는 Radix를 씁니다 — `@radix-ui/react-select`, `@radix-ui/react-checkbox`.

이 저장소는 shadcn 규약 위에 서 있고 이미 `@radix-ui/react-slot`을 씁니다. 네이티브 `<select>`는 드롭다운 안쪽을 꾸밀 수 없어 상태를 전시할 수 없고, 네이티브 체크박스는 표시자를 토큰으로 그릴 수 없습니다. 상태를 보여주는 것이 이 문서의 존재 이유이므로 Radix를 씁니다.

`Input`은 네이티브 `<input>`으로 충분합니다. 새 의존성이 없습니다.

## 1. `Input`

### 컴포넌트

`src/components/ui/input.tsx`. `Button`과 같은 방식으로 `cva`를 씁니다.

- 테두리는 `border-input`, 포커스 링은 `ring-ring`
- 오류는 `aria-invalid`로 나타냅니다 — `Button`이 이미 쓰는 방식이라 같은 자리에 맞춥니다
- `disabled`는 `opacity-50` + `cursor-not-allowed`

### 축

| 축 | 값 |
|---|---|
| `size` | `sm` · `default` · `lg` |
| `state` | `default` · `hover` · `focus` · `disabled` · `invalid` · `readonly` |
| `width` | `hug` · `fill` |

`readonly`는 `disabled`와 다릅니다 — 값을 읽을 수 있고 복사할 수 있으나 고칠 수 없습니다. 어드민에서 자주 쓰이는데 둘을 섞어 쓰는 실수가 흔하므로 축에 넣어 갈라 보입니다.

`type`은 축으로 두지 않습니다. 시각적으로 달라지지 않고 값만 다르므로 `Cases`에서 다룹니다.

### 구조 (Anatomy)

컨테이너 · 값 · 자리표시자 · 앞 아이콘(선택) · 뒤 요소(선택, 지우기 버튼이나 단위 표시)

### 지침

- **자리표시자를 라벨 대신 쓰지 않는다** — 입력을 시작하면 사라져 무엇을 넣는 칸인지 알 수 없게 됩니다
- **오류는 색만으로 알리지 않는다** — 테두리 색과 함께 문구를 답니다. Writing의 오류 메시지 규칙을 따릅니다
- **폭은 기대하는 값의 길이에 맞춘다** — 우편번호 칸이 이름 칸과 같은 폭이면 무엇을 넣는 칸인지 흐려집니다

### 사용 예 (Usage)

검색 상자 · 폼 한 줄(라벨 + 입력 + 도움말) · 표 안 필터 · 금액 입력(뒤에 단위)

### 예외 상황 (Cases)

값이 칸보다 긴 경우 · 읽기 전용 · 오류와 도움말이 함께 있는 경우 · 비밀번호 · 좁은 화면

## 2. `Checkbox`

### 컴포넌트

`src/components/ui/checkbox.tsx`. Radix의 `Checkbox`를 감쌉니다.

- 꺼짐은 `border-input`, 켜짐은 `bg-primary`
- 표시자는 `lucide-react`의 `Check`, 중간 상태는 `Minus`

### 축

| 축 | 값 |
|---|---|
| `state` | `unchecked` · `checked` · `indeterminate` · `disabled` · `focus` |
| `layout` | `standalone` · `with-label` · `with-description` |

`indeterminate`를 축에 넣습니다. 표 전체 선택에서 반드시 쓰이는데 빠뜨리기 쉽습니다.

`size`는 두지 않습니다. 체크박스는 한 크기로 충분하고, 크기를 늘리면 옆 글자와의 정렬이 깨집니다. 그 판단을 지침에 적습니다.

### 구조 (Anatomy)

상자 · 라벨(선택) · 설명(선택)

표시자는 부위로 두지 않습니다. 꺼진 상태에서는 보이지 않으므로 다른 부위와 한 인스턴스에 공존하지 못하고, Radix가 그 DOM을 내부에서 그려 밖에서 표를 붙일 수도 없습니다. 상자의 설명이 표시자를 함께 다룹니다.

### 지침

- **라벨 전체가 누를 수 있는 자리다** — 상자만 누르게 하면 어드민의 조밀한 표에서 맞히기 어렵습니다
- **중간 상태는 '일부 선택'에만 쓴다** — '모름'이나 '해당 없음'을 뜻하지 않습니다
- **체크박스와 라디오를 바꿔 쓰지 않는다** — 여럿 고를 수 있으면 체크박스, 하나만 고르면 라디오입니다

### 사용 예 (Usage)

표의 행 선택 · 표 머리의 전체 선택 · 약관 동의 · 설정 켜고 끄기

### 예외 상황 (Cases)

라벨이 두 줄 이상 · 비활성인데 켜져 있는 경우 · 중첩된 선택 · 좁은 화면

## 3. `Select`

### 컴포넌트

`src/components/ui/select.tsx`. Radix의 `Select`를 감쌉니다. shadcn 구성(`Trigger`·`Content`·`Item`·`Value`)을 따릅니다.

- 트리거는 `Input`과 같은 테두리·높이·포커스 링을 씁니다. 나란히 놓였을 때 어긋나면 안 됩니다
- 목록은 `bg-popover`, 선택된 항목은 `bg-accent`

### 축

| 축 | 값 |
|---|---|
| `size` | `sm` · `default` · `lg` |
| `state` | `default` · `hover` · `focus` · `disabled` · `invalid` |
| `width` | `hug` · `fill` |

`open`은 축에 넣지 않습니다. 처음에는 넣으려 했으나, 열린 목록은 트리거의 변형이 아니라 다른 표면이라 격자의 칸 하나에 담기지 않습니다. 포털된 고정 위치 요소는 행 높이에 계산되지 않아 아래 칸을 덮습니다.

열린 모습은 구조도가 보여줍니다 — 구조도의 미리보기가 열린 인스턴스이고, 목록과 항목이 그 안의 부위입니다.

### 구조 (Anatomy)

트리거 · 값 · 목록 · 항목

화살표와 선택 표시는 부위로 두지 않습니다. Radix가 그 DOM을 내부에서 그려 밖에서 표를 붙일 수 없고, 붙이려면 제품 컴포넌트가 문서 시스템을 알아야 합니다. 트리거의 설명이 화살표를, 항목의 설명이 선택 표시를 함께 다룹니다 — Checkbox의 표시자와 같은 처리입니다.

### 지침

- **선택지가 적으면 라디오를, 많으면 Select를 쓴다** — 둘셋뿐인데 접어 두면 누르는 수만 늘어납니다
- **자리표시자와 기본값을 구별한다** — 고르지 않은 상태와 기본이 골라진 상태는 다릅니다
- **항목 순서에 뜻을 담는다** — 빈도나 크기 순이 알파벳순보다 나은 자리가 많습니다

### 사용 예 (Usage)

표 필터 · 폼의 분류 선택 · 페이지당 행 수 · 상태 변경

### 예외 상황 (Cases)

항목이 아주 많은 경우 · 항목 글이 트리거보다 긴 경우 · 선택지가 하나뿐인 경우 · 비어 있는 목록

## 4. 세 컴포넌트가 함께 지켜야 하는 것

각 문서의 지침에 흩어 두면 서로 어긋나는지 알 수 없습니다. 세 문서 모두 다음을 같은 문구로 적습니다.

- 높이는 같은 `size`에서 서로 같습니다. `sm`은 표와 필터 바, `default`는 폼, `lg`는 단독 입력입니다
- 포커스 링은 셋이 같은 모양입니다
- 오류는 `aria-invalid`로 나타내고 색과 문구를 함께 씁니다
- 비활성과 읽기 전용은 다릅니다

`Foundations`의 `State` 문서가 상태의 표현 규칙을 이미 정하고 있으므로, 세 지침은 그 문서를 가리킵니다. 규칙을 다시 적지 않습니다.

## 5. 문서에 반영되는 것

`registry.ts`에 세 `ComponentMeta`를 더합니다. `category`는 셋 다 `inputs`입니다.

`ComponentsIndex`가 `components`에서 파생하므로 카테고리 구역과 개수는 저절로 따라옵니다. 손으로 고칠 곳이 없습니다.

`nav-config`의 Components 섹션에 세 문서를 더합니다. 순서는 `Button` 뒤에 `Input` · `Select` · `Checkbox`입니다.

각 컴포넌트의 `addedIn`은 `v0.7.0`, `status`는 `stable`입니다.

## 범위 밖

- `Radio` · `Textarea` · `Switch` — 같은 가족이지만 이번에는 셋만 합니다
- 라벨·도움말·오류를 묶는 `Field` 감싸개 — 세 컴포넌트가 자리를 잡은 뒤에 판단합니다
- `Patterns` · `Updates` · `Get started` 채우기
- `useMeasuredTokens` 5벌 중복 해소

## 전역 제약

v0.6.0의 제약을 그대로 잇습니다.

- 작업 브랜치는 `v0.7.0`. `main`에 직접 커밋하지 않습니다
- 임의 값 대괄호 표기 금지 (셀렉터 변형은 허용)
- **언어 규칙** — 구조를 가리키는 이름은 영문, 설명은 한국어. 이미 영문인 용어는 유지. 방향·순서를 가리키는 낱말과 제품 이름은 한국어
- 화면에 나오는 목록·순서·값·날짜를 손으로 적지 않습니다
- 전시 컴포넌트(`components/docs/*`)는 구체적 UI 컴포넌트를 import하지 않습니다
- 문구는 Writing 규칙을 따릅니다
- 테스트 대상은 순수 로직(`data/`, `lib/`, `nav-config`)에 한정합니다. 컴포넌트 렌더링은 단위 테스트하지 않습니다
- `tsconfig`에 `baseUrl`을 추가하지 않습니다
- 각 Task는 `npm run build`와 `npm test` 통과를 완료 조건에 포함합니다
- 커밋 메시지는 한국어 본문, 제목은 Conventional Commits 접두사
