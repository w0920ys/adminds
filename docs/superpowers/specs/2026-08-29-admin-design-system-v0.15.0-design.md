# 어드민 디자인 시스템 v0.15.0 — 레이아웃/네비게이션 재구성 설계

**Context:** v0.14.0(타이포그래피 스케일 재설계)이 `main`에 배포됐다. 이번 회차는 이전에 정리해 둔 v0.14.0 후보 세 갈래(컴포넌트 로드맵/레이아웃·네비게이션/타이포그래피) 중 레이아웃·네비게이션을 다룬다. 사용자가 지정한 순서는 레이아웃·네비게이션 → 남은 로드맵 컴포넌트(Context Menu·Menubar·Resizable) → 마무리 항목이다.

**동기:** 모바일 헤더의 햄버거 버튼 위치, LNB 서랍이 여는 방향, 모바일 서랍이 "Sections" 전체 목록과 현재 섹션 문서를 한 스크롤에 같이 보여주는 방식, 푸터 두 곳의 구성 — 넷 다 사용자가 직접 지정한 변경 대상이다. 넷 다 `src/components/layout/`에 이미 있는 컴포넌트를 고치는 일이라 새 하위 시스템이 아니라 레이아웃 껍데기 하나를 다듬는 일이며, 한 스펙으로 묶는다.

**범위:** `Gnb.tsx`(모바일 헤더 순서) · `Lnb.tsx`(모바일 서랍 위치 + 1depth/2depth 상태 기계) · `DocFooterNav.tsx`(구분선 제거) · `SiteFooter.tsx`(좌우 2단 재구성). 넷 다 `src/components/layout/` 안에서 끝난다. 데스크톱 LNB 위치·TableOfContents·AppShell의 전체 골격은 건드리지 않는다.

---

## 1. GNB — 모바일 헤더 순서

**지금:** `[햄버거][로고]......[검색][테마 토글]` (`Gnb.tsx`). 햄버거 버튼은 `md:hidden`이라 모바일 전용이다.

**바뀔 것:** `[로고]......[검색][테마 토글][햄버거]` — 햄버거를 JSX 트리에서 테마 토글 버튼 뒤로 옮긴다. `onClick`(서랍 열기)·`aria-label`·아이콘(Menu)은 그대로다. 순수 마크업 순서 변경이며 새 상태나 로직이 없다.

**근거:** LNB 서랍이 오른쪽에서 열리게 되므로(2절), 여는 버튼도 같은 쪽에 있는 것이 자연스럽다.

## 2. LNB — 모바일 서랍 위치 + 1depth/2depth 상태 기계

### 위치 (모바일 서랍만, 데스크톱 정적 사이드바는 안 건드림)

지금 `Lnb.tsx`의 모바일 서랍은 `fixed inset-y-0 left-0` + 닫힘 상태 `-translate-x-full` + `border-r`로 왼쪽에서 슬라이드한다. 이걸 `right-0` + 닫힘 상태 `translate-x-full` + `border-l`로 바꿔 오른쪽에서 슬라이드하게 한다. `md:static md:h-full md:shrink-0 md:translate-x-0`(데스크톱 규칙)는 그대로 둔다 — 데스크톱에서는 지금처럼 왼쪽 정적 사이드바로 남고, xl 이상의 목차(TableOfContents, 본문 오른쪽)와 자리가 겹치지 않는다.

### 상태 기계

`Lnb.tsx` 내부에 뷰 상태를 하나 둔다:

```ts
type LnbView = { kind: 'section' } | { kind: 'sections' }
```

- **서랍이 열릴 때**: 뷰는 항상 `{ kind: 'section' }`으로 시작한다 — 현재 경로의 섹션(`findSection(pathname)`, 기존 함수 그대로 재사용)의 문서 목록을 보여준다. 지금 서랍을 열면 바로 보이던 것과 체감상 같다.
- **2depth(`{ kind: 'section' }`) 화면**: 맨 위에 뒤로가기 버튼(ChevronLeft 아이콘 — `DocFooterNav.tsx`가 이미 쓰는 아이콘과 통일)을 추가한다. 누르면 뷰가 `{ kind: 'sections' }`로 바뀐다.
- **1depth(`{ kind: 'sections' }`) 화면**: 지금 모바일 전용으로 이미 그리고 있는 "Sections" 목록(`sections.map(...)`, `Lnb.tsx:95-110`)을 그대로 이 화면의 본문으로 흡수한다 — 별도 블록이 아니라 1depth 자체가 된다. 섹션을 탭하면 뷰가 `{ kind: 'section' }`으로 바뀌고, 그 섹션의 문서 목록이 2depth에 나온다(경로 이동은 하지 않는다 — 섹션을 탭하는 것은 화면 전환이지 네비게이션이 아니다. 실제 이동은 2depth에서 문서를 탭할 때 일어난다).
- **문서를 탭할 때**: 기존과 동일하게 그 문서로 즉시 이동하고 서랍이 닫힌다(`onClose` 그대로).
- **서랍이 닫힐 때**: 뷰 상태를 버린다(초기화하거나, 닫힘 시점에 그냥 무시하고 다음 열림 때 다시 `{ kind: 'section' }`으로 시작). 뒤로 가서 다른 섹션을 보다가 닫았다 다시 열어도, 항상 현재 경로 기준 2depth부터 시작한다 — "마지막으로 보던 자리 기억"은 하지 않는다(간단함 우선, 실제로 필요하다는 신호가 없다).
- **1depth에서 섹션을 탭하고 그 2depth에서 뒤로가기를 다시 누르면**: 1depth로 돌아간다(같은 세션 안에서는 정상적인 왕복). 이건 새 개념이 아니라 뒤로가기 버튼 하나로 자연히 따라오는 동작이다.

### 시각 요소

- 1depth 헤더: "Sections" 라벨(기존 문구 유지) + 닫기(X) 버튼.
- 2depth 헤더: 뒤로가기(ChevronLeft) + 섹션 라벨(대문자, 기존 스타일 `text-11 font-bold tracking-widest` 유지) + 닫기(X) 버튼.

## 3. DocFooterNav — 구분선 제거

`DocFooterNav.tsx`의 `<footer className="mt-16 flex flex-col gap-4 border-t pt-6">`에서 `border-t`를 뺀다. `pt-6`도 시각적으로 의미가 없어지므로 함께 정리한다(패딩 대신 `mt-16`이 유일한 구분 여백이 된다). 본문과 이 푸터 블록 사이에는 선 없이 여백만 남는다.

## 4. SiteFooter — 좌우 2단 재구성

**지금:** 로고 없이 두 nav 그룹(섹션 이동/연락처)이 가로로 늘어서고, 그 아래에 copyright 한 줄.

**바뀔 것:** 좌우 2단 구조.
- **왼쪽**: 로고 배지 + "서비스 대시보드"(GNB와 같은 아이콘·문구, `Command` 아이콘의 `bg-primary text-primary-foreground` 배지) 위에, 그 아래 copyright 줄(`© {year} sunwooyoon. All rights reserved.`, 기존 문구 그대로)을 세로로 쌓는다.
- **오른쪽**: 기존 두 `<nav>`(섹션 이동="Menu", 연락처="Contact")를 각각 세로 리스트인 별도 컬럼으로 나란히 놓는다(지금처럼 가로로 늘어서는 한 줄이 아니라, 두 개의 세로 목록이 나란한 2컬럼).
- **반응형**: 모바일에서는 좌우 2단이 위아래로 쌓인다(왼쪽 블록 먼저, 오른쪽 2컬럼이 그 아래).

두 `<nav>`의 `aria-label`("섹션 이동"/"연락처")과 링크 목록·href는 그대로 재사용한다 — 배치만 바뀐다.

## 테스트 전략

이 프로젝트의 Vitest는 `node` 환경(jsdom 없음)이라 컴포넌트 렌더링 테스트를 쓰지 않는다 — 기존 관례와 동일하게 `npm run build`(tsc+vite) 통과와 개발 서버에서 `getComputedStyle`/`read_page`/스크린샷으로 실측 검증한다.

- LNB 상태 기계는 순수 로직이 거의 없다(뷰가 두 값을 오가는 로컬 `useState`뿐, `findSection` 같은 기존 pure 함수를 그대로 재사용). 새 pure 함수가 생기지 않으므로 새 노드 테스트도 없다 — 브라우저에서 서랍 열기 → 뒤로가기 → 섹션 전환 → 문서 탭까지 전체 흐름을 실제로 눌러 확인한다.
- GNB·DocFooterNav·SiteFooter는 마크업 순서/클래스 변경이라 브라우저 스크린샷으로 확인한다.

## 범위 밖

- 데스크톱 LNB 위치 (왼쪽 정적 사이드바 그대로)
- TableOfContents 위치나 로직
- AppShell의 전체 3단 레이아웃 골격
- 남은 로드맵 컴포넌트(Context Menu·Menubar·Resizable) — 사용자가 이번 다음 순서로 이미 지정함
- `changedIn`/`updatedAt` 드리프트 가드 테스트, Badge 명암비 — 별도 마무리 항목으로 이미 분류됨

## 자체 검토

**플레이스홀더 스캔:** 없음.
**내부 일관성:** 4개 절이 서로 다른 파일을 다루고 상태·데이터를 공유하지 않는다 — 충돌 없음.
**범위 점검:** 넷 다 `src/components/layout/` 안에서 끝나는 마크업/상태 변경이라 하나의 계획으로 묶기에 적절하다. 분해가 필요할 만큼 크지 않다.
**모호성 점검:** 서랍 열림 시 초기 뷰(2depth부터), 문서 탭 동작(즉시 이동+닫힘), 구분선 처리(완전 삭제), 푸터 배치(좌우 2단) — 전부 사용자 확인을 거쳐 하나의 해석으로 고정했다.
