# 어드민 디자인 시스템 v0.6.0 설계

> v0.5.0 피드백을 받은 뒤 이어지는 회차입니다. v0.5.0은 병합하지 않은 채 v0.6.0을 그 위에 쌓습니다.

## 배경

v0.5.0에서 섹션 제목을 전부 한국어로 통일했습니다. 결과를 본 사용자가 방향을 뒤집었습니다 — 구조를 가리키는 이름은 영문으로 두고, 한국어는 설명에만 씁니다.

되돌리지 않고 v0.6.0에서 방향만 바꿉니다. v0.5.0이 아직 병합되지 않았으므로 커밋 이력을 뒤집는 것보다 다음 회차에서 새 규칙을 적용하는 편이 이력이 정직합니다.

이 회차의 항목은 여덟 가지입니다.

---

## 1. 언어 규칙을 뒤집는다

### 새 규칙

**구조를 가리키는 이름은 영문, 설명은 한국어.**

- **영문으로 쓰는 것** — 섹션 제목(= 목차 항목), 페이지 이름, UI 라벨(버튼·배지·범례), 속성 이름, 코드 식별자
- **한국어로 쓰는 것** — 설명문, 표 안의 서술, 지침의 규칙 문장, 주석
- **이미 영문인 용어는 그대로 둔다** — 새로 한국어로 바꾸지 않습니다. 그 용어를 영문으로 유지한 채 나머지를 한국어로 설명합니다.

이 규칙은 v0.5.0의 규칙을 대체합니다. `WritingPage`의 `한국어와 영어` 섹션이 옛 규칙을 명문화한 자리이므로 그 본문도 새 규칙으로 다시 씁니다.

## 2. Anatomy 지시선이 겹치지 않게 한다

지금은 좌우 지시선이 컴포넌트 근처에서 서로 겹쳐, 어느 선이 어느 라벨의 것인지 분간되지 않습니다.

**해결**: 같은 쪽에 놓인 지시선들이 서로 다른 x 좌표에서 꺾이게 합니다. 라벨이 위에서 아래로 놓인 순서대로 꺾임점을 컴포넌트에서 멀어지는 방향으로 어긋나게 두면, 수직 구간이 서로 다른 세로선 위에 놓여 겹치지 않습니다.

부품이 가리키는 지점의 y 좌표가 같아도 꺾임 x가 다르므로 수평 구간만 나란해지고, 수평 구간끼리는 y가 달라 겹치지 않습니다.

## 3. 제목에서 URL을 복사한다

`h2`·`h3`에 마우스를 올리면 제목 오른쪽에 link 아이콘이 나타납니다. 누르면 그 절을 가리키는 전체 URL이 복사되고 아이콘이 check로 바뀝니다. 잠시 뒤 link로 돌아갑니다.

`TableOfContents`가 이미 제목마다 `id`를 붙이므로 그 `id`를 그대로 씁니다. 아이콘은 마우스가 없는 환경에서도 키보드 포커스로 닿을 수 있어야 합니다.

복사에 실패하면 아이콘이 check로 바뀌지 않고 실패를 알립니다 — `CopyValue`가 이미 이 방식을 쓰므로 같은 상태 기계를 따릅니다.

## 4. LNB 하위 항목의 모서리를 없앤다

`Lnb`의 `depth > 0` 항목에서 `rounded-md`를 뺍니다. 상위 항목은 그대로 둡니다. 들여쓰기의 왼쪽 선과 각진 모서리가 만나 하위 관계가 더 분명해집니다.

## 5. 목차를 컨테이너 위에 sticky로 붙이고 스크롤바를 감춘다

지금 목차는 스크롤 컨테이너(`main`)의 형제입니다. 사용자는 목차가 컨테이너 **위에** 붙어 있기를 원하고, 컨테이너의 스크롤바가 보이지 않기를 원합니다.

**해결**: 목차를 `main` 안으로 옮겨 `position: sticky`로 둡니다. `main`은 그대로 스크롤 컨테이너로 남습니다(사용자가 선택한 방향). `main`의 스크롤바는 감춥니다.

- `main` 안을 본문과 목차 두 칸으로 나눕니다. 목차 칸은 `sticky`, `top-0`
- `main`에 스크롤바를 감추는 유틸리티를 적용합니다. `scrollbar-width: none`과 `::-webkit-scrollbar { display: none }`을 함께 둡니다 — 앞은 Firefox, 뒤는 WebKit입니다
- 스크롤 자체는 막지 않습니다. 감추는 것은 막대뿐입니다

목차의 활성 판정은 `main`을 기준으로 삼으므로 바뀌지 않습니다. 다만 목차가 `main` 안으로 들어가면 `main.querySelectorAll('h2, h3')`가 목차 자신의 제목까지 잡을 위험이 생깁니다. 목차의 제목은 지금도 `p`이므로 그대로 두면 됩니다 — 옮긴 뒤 수집 결과가 늘지 않았는지 확인합니다.

## 6. 위계에 맞춰 간격을 넓힌다

섹션 사이를 120px로 넓히고, 그 아래 위계도 비율에 맞춰 조정합니다.

| 자리 | 지금 | 바꿀 값 |
|---|---|---|
| 섹션 사이 (`DocPage`) | 48px (`gap-12`) | 120px (`gap-30`) |
| 섹션 제목과 내용 사이 (`DocSection`) | 16px (`gap-4`) | 24px (`gap-6`) |
| 섹션 안 블록 사이 (`ComponentPage`) | 32px (`gap-8`) | 48px (`gap-12`) |
| 페이지 머리글 안 (`DocPage` header) | 12px (`gap-3`) | 16px (`gap-4`) |

`gap-30`은 Tailwind v4의 동적 간격 스케일에서 `30 × 0.25rem = 7.5rem = 120px`입니다. 이 저장소는 `--spacing`을 재정의하지 않으므로 기본값이 적용됩니다. 대괄호 임의 값이 아니므로 전역 제약을 지킵니다.

구현할 때 브라우저에서 실제 계산값이 120px인지 확인합니다. Tailwind가 이 배수를 만들어내지 못하면 `--spacing-section` 토큰을 만들어 쓰고, 그때도 대괄호 표기는 쓰지 않습니다.

## 7. Overview 페이지에 개요를 싣는다

지금 `Foundations`와 `Components`의 overview는 하위 문서로 가는 카드 목록뿐입니다. 이동 경로만 있고 그 섹션이 무엇인지 설명하지 않습니다.

**해결**: 카드 목록 위에 `Overview` 섹션을 둡니다. 그 섹션이 무엇을 다루고, 어떤 순서로 읽으면 되고, 무엇을 정하지 않는지 적습니다. 하위 문서 카드 목록은 그 아래 `Pages` 섹션으로 내립니다.

overview 페이지에는 이전/다음 버튼이 없다는 v0.4.0의 규칙은 그대로입니다.

## 전역 제약

v0.5.0의 제약을 그대로 잇되 언어 규칙만 바뀝니다.

- 작업 브랜치는 `v0.6.0`. `v0.5.0`에서 딴 뒤 `main`에 직접 커밋하지 않습니다
- 색·간격·radius·shadow 값을 하드코딩하지 않습니다. 임의 값 대괄호 표기(`[3px]`, `[#abc]`, `[calc(...)]`) 금지 — `[&_svg]:size-4` 같은 임의 셀렉터 변형은 허용
- **언어 규칙(새것)** — 구조를 가리키는 이름은 영문, 설명은 한국어. 이미 영문인 용어는 유지
- 화면에 나오는 목록·순서·값·날짜를 손으로 적지 않습니다. 네비게이션·목차·footer 메뉴는 파생이어야 합니다
- 전시 컴포넌트(`components/docs/*`)는 구체적 UI 컴포넌트를 import하지 않습니다
- 문구는 Foundations의 Writing 규칙을 따릅니다 — `~합니다`체(요청만 `~하세요`), 느낌표·물음표 안 씀, 항목 이름과 값에 작은따옴표, 완전한 문장에만 마침표, 번역투 회피
- 테스트 대상은 순수 로직(`data/`, `lib/`, `nav-config`)에 한정합니다
- `tsconfig`에 `baseUrl`을 추가하지 않습니다 (TypeScript 6의 `TS5101` 하드에러)
- 각 Task는 `npm run build`와 `npm test` 통과를 완료 조건에 포함합니다
- 커밋 메시지는 한국어 본문, 제목은 Conventional Commits 접두사
